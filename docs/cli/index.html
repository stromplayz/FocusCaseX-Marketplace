The FCX CLI

Install the marketplace anywhere Node 18 runs, host it on your own machine, and script the catalog — every fcx command, in one place.

The CLI is the npm package focuscasex (binary fcx), maintained in the FCX-NPM repo. The install guide keeps the short version.

The FocusCaseX marketplace and its WorkBenches are installable anywhere Node 18 runs. The fcx command line installs from the same catalog the Android app browses — same items, same FCX-XXXXXX install codes — and it can host the registry on your own machine so every computer in the clinic LAN installs from it. Both ends update from the same pipeline, so the CLI and the app never drift apart.

Install

Install the CLI

Install once

Node 18 or newer, then one command in a terminal — Linux, macOS or Windows:

npm install -g github:stromplayz/FCX-NPM

Also published to npm as focuscasex — the GitHub install above works today. Once the npm token is configured on the repo, npm install -g focuscasex works too. Source and releases: github.com/stromplayz/FCX-NPM.

First steps

Three commands to start

  1. Run fcx doctor — check Node, the workspace folder, the catalog cache and marketplace reachability.
  2. Run fcx sync — refresh the catalog cache from the public marketplace.
  3. Run fcx workbench list — see every WorkBench with its install code.
Reference

Command reference

Every command with its exact syntax. Anything in brackets is optional; the quick version lives on the install guide's CLI section.

Command What it does
fcx --versionPrint the CLI version — it tracks the platform release.
fcx doctor [--offline]Check Node, the workspace folder, the catalog cache and marketplace reachability. With --offline it warns instead of failing and falls back to the cache.
fcx syncRefresh the catalog cache from the public marketplace.
fcx catalog [kind] [--json]List everything installable — Extensions, capsules, themes, templates — with an optional kind filter; --json prints the list for scripts.
fcx workbench listList WorkBenches with their install codes.
fcx workbench show <id-or-code>Print the full description and every piece inside. Accepts an item id, an FCX-XXXXXX code, or a name substring.
fcx workbench install <id-or-code> [--dir D]Install a WorkBench into a local workspace folder — --dir D picks the destination — and print a per-item summary of everything that landed.
fcx serve [--port 4319]Host the registry locally — health, catalog and WorkBench bundle endpoints — and print the local and LAN URLs.
fcx openOpen the full FocusCaseX workspace in your browser — the same features as the Android app.
fcx mcpPrint MCP pairing info plus ready-to-paste agent setup snippets. The full walkthrough: MCP & AI agents.
Hosting

Host the registry on the clinic LAN

fcx serve turns the machine it runs on into the registry for the whole clinic. It serves the catalog and WorkBench bundles over HTTP — port 4319 by default, --port to change it — and prints two URLs when it starts: one for the machine itself and one for the LAN. Point a browser at the LAN URL from any computer on the clinic network and the same catalog is right there.

What it serves comes from the local catalog cache — run fcx sync and the LAN copy refreshes from the public marketplace.

Endpoint What it serves
/healthStatus and version — a quick check that the server is up.
/api/catalogThe full catalog, in the same shape the app installs from.
/api/workbenchesEvery WorkBench with its install code.
/api/workbenches/<id>One WorkBench bundle, ready to install.
On disk

Where things live

Two places, both under your home folder.

Path What it is
~/.focuscasex/cache/catalog.jsonThe catalog cache — fcx sync refreshes it, fcx serve shares it, fcx doctor checks it.
~/.focuscasex/workspace/<workbench-id>/One folder per installed WorkBench, with every piece inside.
Updates

Staying updated

Both ends move together. A GitHub Action in the FCX-NPM repo syncs the CLI from the private source repo, rebuilds it and publishes it whenever the platform ships. To update, run the same install command again — npm install -g github:stromplayz/FCX-NPM — and fcx --version confirms the build you have.

When something's off

Troubleshooting

Four things come up most; each has a short answer.

What you see What to do
fcx: command not foundnpm's global bin folder is not on your PATH. Add it to PATH — or reinstall with the install command and open a fresh terminal.
catalog fetch failsRun fcx sync to refresh the cache, or check the network. fcx doctor --offline passes with a cached catalog, so installs keep working without the network.
port already in useStart the server on another port: fcx serve --port <other>.
version mismatchReinstall with the same command — npm install -g github:stromplayz/FCX-NPM — then check fcx --version.
