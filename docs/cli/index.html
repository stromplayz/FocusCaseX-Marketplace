The FCX CLI

The interactive console, the Extensions storefront, the licence flow and the LAN registry host — every fcx command, in one place.

The CLI installs from this site's own registry — one curl command, binary fcx — and is maintained in the FCX-NPM repo. The install guide keeps the short version.

The FocusCaseX marketplace and its WorkBenches are installable anywhere Node 18 runs. The fcx command line browses the same catalog the Android app browses — same items, same FCX-XXXXXX install codes — from an interactive console (bare fcx on a terminal), a terminal storefront (fcx marketplace) or plain commands. It can also host the registry on your own machine so every computer in the clinic LAN installs from it. Both ends update from the same pipeline, so the CLI and the app never drift apart.

Install

Install the CLI

Install once

One command in a terminal — works on Linux, macOS or Windows (WSL/Git Bash):

curl -fsSL https://stromplayz.github.io/FocusCaseX/install.sh | bash

The registry installer checks Node 18+, installs fcx to ~/.focuscasex/bin and wires your PATH. Source and releases: github.com/stromplayz/FCX-NPM.

Licence

The licence flow

One code per device

Install does not carry the licence. Your FocusCaseX owner issues one FCX-XXXXXX code per device. In a terminal:

fcx login
  1. Run fcx login and answer the three prompts — your licence email, password and the FCX-XXXXXX code from your licence email (alias: fcx activate).
  2. The machine becomes a trusted device under the licence and counts against the code's device limit.
  3. Trusted devices never re-enter a code — fcx login on a signed-in machine re-verifies the stored licence instead of asking again. Run fcx status to confirm, and fcx device to see exactly what the owner sees on the licence record.

Codes, device limits and keepalive. Codes are issued by your FocusCaseX owner for your licence email; a machine counts against the code's device limit — a licence moves by revoking the old machine and activating the new one. fcx alive start runs a small daemon that pings the licence registry on a schedule, so the licence record shows this machine as current between sign-ins (fcx alive status checks it, fcx alive stop stops it). Full details: how codes, devices and revocation work.

First steps

Three commands to start

  1. Run fcx setup — guided setup: pick the workspace folder, sync the catalog, sign in, install a first WorkBench.
  2. Run fcx marketplace — browse and install Extensions from the terminal.
  3. Run fcx status — confirm the device licence.
The console

The interactive console

Bare fcx on a real terminal

Run fcx with no arguments in a terminal — or fcx menu — and the console opens: the whole CLI behind arrow-key menus. Account, Extensions, WorkBenches, diagnostics, keepalive and the clinic workspace, with Esc to go back a level.

When the output is piped — or FCX_NON_INTERACTIVE=1 is set — bare fcx prints the plain help text instead, and every command on this page still works on its own.

Marketplace

The storefront in the terminal

fcx marketplace

fcx marketplace opens the Extensions storefront: browse by category — Featured, Clinical, Productivity and more — press / to search, enter an item page for the description, rating and install code, and press i to install in place. Alias: fcx market. Bare fcx install opens it too.

Everything it installs lands under ~/.focuscasex/workspace/. To switch an Extension on in the app, install it there by the same code: Settings → Extensions → install by code.

Command reference

Every command with its exact syntax. Anything in brackets is optional; the quick version lives on the install guide's CLI section.

Console and setup

fcx setupGuided setup: pick the workspace folder, sync the catalog, sign in, install a first WorkBench.

fcx vitals [--offline]Environment health check, eight checks — Node, FCX home, config, licence, catalog cache, marketplace, keepalive, installed items (alias: fcx doctor). With --offline it skips the network checks.

fcx catalog [kind] [--json]Quick catalog listing — every kind, with install codes; --json prints the list for scripts.

fcx workbench show <id-or-code>Print the full description and every piece inside. Accepts an item id, an FCX-XXXXXX code, or a name substring.
fcx workbench install <id-or-code> [--dir D]Install a WorkBench into a local workspace folder — --dir D picks the destination — and print a per-item summary of everything that landed.
fcx syncRefresh the catalog cache from the public marketplace.
System and diagnostics
fcx stats [--json]Local usage dashboard — commands run, installs, recent activity.
fcx alive start|stop|status|runKeepalive daemon — pings the licence registry on a schedule so the licence record shows this machine as current.
fcx config list|get|set|resetCLI settings — workspace folder, keepalive interval, appearance.

fcx help [command]Print the grouped help list, or one command in detail — fcx help setup, fcx help serve. Per-command --help works too.
Hosting

Host the registry on your clinic network

fcx serve turns the machine it runs on into the registry for the whole clinic. It serves the catalog and WorkBench bundles over HTTP — port 4319 by default, --port to change it — and prints two URLs when it starts: one for the machine itself and one LAN address per network card. When a clinic network exists, point a browser at the LAN URL from any computer on it and the same catalog is right there.

No clinic network? Nothing breaks — the web workspace remains the way in, and it opens as usual from anywhere. The local URL on the serve machine always works too.

What it serves comes from the local catalog cache — run fcx sync and the shared copy refreshes from the public marketplace.

Endpoint What it serves
/healthStatus and version — a quick check that the server is up.
/api/catalogThe full catalog, in the same shape the app installs from.
/api/workbenchesEvery WorkBench with its install code.
/api/workbenches/<id>One WorkBench bundle, ready to install.
Diagnostics

Local usage stats

fcx stats prints the local usage dashboard — commands run, installs and uninstalls, sign-ins, syncs, keepalive actions and updates — plus the most-used commands and the last few events. --json dumps the same numbers for scripts.

Settings

CLI settings

fcx config reads and writes ~/.focuscasex/config.json: fcx config list prints every key and value, fcx config get <key> and fcx config set <key> <value> read and write dotted keys — workspaceDir, keepalive.intervalMinutes, appearance — and fcx config reset restores the defaults.

On disk

Where things live

Everything lives under one folder in your home directory.

Path What it is
~/.focuscasex/config.jsonCLI settings — fcx config reads and writes it.
~/.focuscasex/installed.jsonWhat is installed — fcx install list reads it, fcx uninstall updates it.
~/.focuscasex/stats.jsonlUsage events behind fcx stats (JSON lines, append only).
~/.focuscasex/alive.pid · alive.logThe keepalive daemon's pid file and ping log — fcx alive.
~/.focuscasex/cache/catalog.jsonThe catalog cache — fcx sync refreshes it, fcx serve shares it, fcx vitals checks it.
~/.focuscasex/workspace/<workbench-id>/One folder per installed WorkBench, with every piece inside.
~/.focuscasex/workspace/extensions/<id>/One folder per installed Extension — capsules, themes, templates and snippets follow the same pattern.
Updates

Staying updated

Both ends move together. Run fcx update to compare your build with the registry — when a newer CLI ships, it prints the one-line command to run. Or re-run the install command from the top of this page; fcx --version confirms the build you have afterwards. The app and the CLI ship from the same pipeline, so a release lands on both ends together.

When something's off

Troubleshooting

Six things come up most; each has a short answer.

What you see What to do
fcx: command not foundThe installer puts fcx in ~/.focuscasex/bin and wires your PATH, but a terminal opened before the install will not see it. Open a fresh terminal and run fcx again.
catalog fetch failsRun fcx sync to refresh the cache, or check the network. fcx vitals --offline passes with a cached catalog, so installs keep working without the network.
This screen needs an interactive terminalThe console and the marketplace are full-screen views — they print this hint when the output is piped. Run them in a real terminal, or use the non-interactive paths: fcx catalog, fcx install <id-or-code>.
port already in useStart the server on another port: fcx serve --port <other>.
version mismatchRun fcx update — it prints the one-line command when a newer build ships — or re-run the install command from the top of this page, then check fcx --version.
the FCX- code is refusedCodes are exact — paste rather than retype, and make sure it is the code issued for your licence email. If the refusal says the device limit is full, your clinic owner moves the licence: the old machine is revoked, a fresh code is issued, and this machine activates. How devices and limits work.
