What MCP gives a clinic

Read your clinic. Write through it. Nothing moves without you.

The FocusCaseX MCP server lets AI agents — Claude, Cursor, VS Code and anything else that speaks MCP — read the clinic and write through it: patients, appointments, records, inventory, Extensions, capsules, themes. Nothing moves without the owner: agents pair before they touch anything, every agent carries its own scopes, and its writes arrive as pending requests you approve. Around 32 tools cover three kinds of work — reads, writes that wait for your confirmation, and builders (the WorkBench Builder, the Capsule Builder) that draft real add-ons for your sign-off.

Your agent thinks in its chat window; the tools run against the same clinic install you use — the hosted workspace or the app on your device. You hold the approval layer for all of it.

Pairing

Pair an agent

Every connection starts in the app and ends with a token you issued.

  1. In the app, open Settings → MCP → Connect agent. A 6-digit pairing code appears — the QR beside it encodes the same pairing details.
  2. Point the agent at the MCP server (endpoints below) and have it POST the code to the pairing endpoint with the scopes it requests: read, write, build.
  3. Approve the pending request under Settings → MCP — check the agent's name and device first. Deny, and it stays locked out.
  4. An access token is issued to the agent with exactly the scopes you chose — nothing more.
  5. Pending requests and issued tokens are managed on the same tab — change scopes or revoke a token any time.

Writes wait for you. Write actions never apply on their own — each one surfaces as a pending action you approve in the app. The 6-digit code expires quickly, so pairing only completes while someone is at the screen.

Endpoints

Server endpoints

Every agent config points at the MCP server; pairing goes through its own endpoint. The on-device app serves both on its local URL.

MCP server https://focuscasex.vercel.app/api/mcp/server Every agent config below points here.
Pairing POST https://focuscasex.vercel.app/api/mcp/pair The agent POSTs its 6-digit code and requested scopes here.
On-device http://<device-ip>:8080/api/mcp/server The app on your phone or tablet serves the same endpoints on its local URL — the exact address is shown under Settings → MCP.
Agent setups

Set up your agent. Every major client, one snippet each.

Pick your client, paste its snippet where it keeps configs, and put a token in the Authorization slot. Mint one by pairing in the app — the 6-digit code or the QR — or issue a personal token under Settings → MCP. The snippets below point at the public web endpoint; an on-device install swaps in the address it shows under Settings → MCP.

Use the web endpoint when you work in the hosted workspace, the device address when the records live on the phone or tablet in the room. Both pair the same way; both log to the same audit log. Headless clients that can't show a pairing screen can use a personal token instead — Settings → MCP → Issue token — as a Bearer header, with the same scopes.

Scopes and safety

Three scopes. You hold the approval layer.

Read Search patients, open records, list appointments, check stock. Reading changes nothing.
Write Book visits, add notes, install capsules and Extensions. Every write shows a human-readable diff first.
Build Draft capsules, Extensions and whole WorkBenches with the builders — you preview the result, then approve the install.
Approve before run Write actions surface as pending actions in the app. Nothing applies until you tap Approve.
Revoke any time Tokens are managed under Settings → MCP. Revoking ends the agent's access on its next call and clears its pending actions.
The code expires quickly A 6-digit pairing code nobody approves simply dies — there is no way in without you at the screen.
