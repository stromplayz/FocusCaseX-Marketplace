The short version

What is FocusCaseX

FocusCaseX is an offline-first clinic workspace for eye care. It runs on your device — a phone, a tablet, a computer — and your records live there with it. There is no server to rent and nothing to host: install it, sign in once, and the clinic is open.

A day in it looks like this: you register a patient and the chart file creates itself, you run the refraction and exam flows, you write notes as plain markdown, and the boards — appointments, recalls, billing, stock — read the same files and show the day at a glance. Pages stay readable and printable no matter what.

Three ideas carry the design:

  1. Pages are markdown. Every clinical page is a plain text file you can read, print and keep. No opaque database, no lock-in.
  2. Capsules are building blocks. A short block pasted into any page renders a live board — appointments, vitals, recalls.
  3. Extensions are features. Small add-ons from the marketplace — an extra panel, an automation, a quick reference — installed in one tap, removed just as easily.

Two ways to run it. The web workspace at focuscasex.vercel.app opens in any browser, anywhere — nothing to install. The Android app carries the clinic on phones and tablets, fully offline. Sharing a clinic over a local network happens only when the clinic network exists; with no clinic network, the web app still opens as usual. Both ends run under one licence — the FCX-XXXXXX code your clinic owner issued — and the FCX CLI (fcx) brings the same catalog to any computer with a terminal.

For clinics, non-technical

Getting started

Seven steps from nothing to a working clinic. Nothing here needs a technical person.

  1. Open FocusCaseX. The quickest start is the web workspace — open focuscasex.vercel.app in a browser. For phones and tablets, the install guide links the latest Android build; download it, allow the install when Android asks, and open FocusCaseX from your app list.
  2. Sign in. Use your licence email and password — the account your licence runs on. Tick Keep me signed in and the next visit skips the form.
  3. Activate the device, once. A device the licence has not met yet asks for the FCX-XXXXXX code from your licence email. Type it once — the device is remembered from then on and never asks again.
  4. Register your first patient. Open the Patients board, tap register, and the patient file and MR number create themselves.
  5. Run the day from the boards. Appointments, examination, dispensing and billing are boards in the sidebar. Record vision, fill the workup, write the plan — everything lands in the patient's chart file.
  6. Add what your clinic needs. Open Settings → Marketplace and browse — Extensions add features, capsules add boards, themes change the look, templates drop in ready-made notes. Every install is one tap, and you see exactly what will be added before it lands.
  7. Let it update itself. The app checks for updates on its own and tells you when one is ready. The web workspace is always current. Nothing to revisit, no store page.

Sharing with the front desk. When your clinic has its own network, the workspace can be shared across it — hosting the registry with fcx serve covers it. No clinic network? The web app still opens as usual — everyone signs in at focuscasex.vercel.app from wherever they are.

Deeper detail lives on the Getting started page — requirements, the activation screen in full, and uninstalling.

For computers

Set up the CLI

The fcx command brings the marketplace, the WorkBenches and the licence flow to any computer that runs Node 18 — macOS, Linux or Windows (WSL/Git Bash).

Install it — one command

curl -fsSL https://stromplayz.github.io/FocusCaseX/install.sh | bash

The installer checks Node 18+, installs the fcx command and wires your PATH. Open a fresh terminal afterwards. Source and releases: github.com/stromplayz/FCX-NPM.

Run the guided setup

fcx setup walks through four steps and finishes with a summary checklist:

  1. Workspace folder — where installed items live on this machine. It checks the folder is writable before moving on.
  2. Catalog — syncs the marketplace catalog into a local cache, so browsing and installs work even when the network is slow.
  3. Sign in — your licence email, password and the FCX-XXXXXX code issued for this machine. Skippable if you want to set up first and sign in later.
  4. First WorkBench — pick a bundle and install it, or skip and browse the marketplace first.

Sign in to the licence

fcx login (alias: fcx activate) asks three things: your licence email, your password, and the FCX-XXXXXX code your clinic owner issued for this machine — one code per device. When it passes, this computer becomes a trusted device under the licence and counts against the code's device limit. Trusted machines never re-enter a code: run fcx login again on a signed-in machine and it re-verifies quietly.

Confirm with fcx status — it prints the licence email and how many of the device limit are in use — and fcx device for the full identity card of this machine.

First commands

  1. Run fcx status — confirm the device licence.
  2. Run fcx marketplace — browse the storefront in the terminal: categories, search, item pages, install in place.
  3. Run fcx install <id-or-code> — install any catalog item directly, by item id or by its FCX-XXXXXX code.

To switch an Extension on in the app as well, install it there by the same code: Settings → Marketplace → Install by code. The CLI copy and the app copy are separate installs of the same catalog item.

Authoring

Create your own Extension

Everything installable in FocusCaseX is described by one catalog entry plus a folder of small files. No build tools, no bundler — a text editor and the fcx command are enough. This guide walks a working Extension end to end; the same text lives on the Extensions authoring page.

The five kinds

Pick the kind that matches what you are building — the kind decides which files the installer fetches and where they land:

  • Extension — a tool that adds a feature: commands, panels, automations. Two files: manifest.json + main.js. (The first kind in every example below.)
  • Capsule — a ready-made board or page section. A spec.mdui layout file, plus optional style.css and logic.mdui.
  • Theme — the workspace look. One JSON file of design tokens.
  • Template — a pre-written clinical note or letter. One markdown file.
  • Snippet — a small interface tweak. One CSS file.

A WorkBench is the sixth entry kind — a bundle that installs many items at once. It is assembled from published items, so build an Extension or two first if you want to ship one.

What an installed item looks like

The CLI installer fetches exactly the files the catalog entry lists and writes them into a folder named after the item, one folder per kind. An Extension always lands as manifest.json and main.js (plus any extra files the entry lists); a capsule keeps its spec.mdui, style.css and logic.mdui; a theme its JSON; a template its markdown; a snippet its CSS. Every install is registered in the CLI's installed list, which is what fcx install list and fcx uninstall read.

How the catalog describes an item

A real entry from the marketplace catalog — the Heading Numbering Extension — so you can see the exact shape:

{ "id": "plugin:heading-numbering", "kind": "plugin", "name": "Heading Numbering", "tagline": "Auto-numbers H2/H3 headings in the reading view using an injected CSS counter (cleaned up on unload).", "description": "Auto-numbers H2/H3 headings in the reading view using an injected CSS counter (cleaned up on unload).", "author": "FocusCaseX originals", "version": "1.0.0", "category": "Writing", "tags": ["plugin", "writing"], "icon": "ListTree", "rating": 4.1, "reviews": 64, "downloads": 4207, "released": "2026-01-24", "verified": true, "featured": false, "meta": { "pluginId": "heading-numbering" }, "files": { "manifest": "plugins/heading-numbering/manifest.json", "main": "plugins/heading-numbering/main.js" } }

The rules that matter:

  • id is kind:slug — plugin:hello-clinic-note, capsule:ui-today, theme:mono-ink. The slug is the folder name under plugins/, capsules/, themes/, templates/ or snippets/ in the site repo.
  • files points at those paths — for an Extension the keys are manifest and main; a capsule lists spec (plus style, logic); a theme lists vars; a template lists body; a snippet has a top-level file.
  • meta carries the bare id — pluginId, capsuleId, themeId, templateId — matching the manifest's own id.
  • rating, reviews, downloads, released, verified and featured are marketplace metadata — the review fills those in; you can leave them out of a new entry.

The minimal Extension — a worked example

"Hello clinic note" — one command and one small stylesheet, in the same shape as the shipped samples. Two files, nothing else.

File 1 of 2 — plugins/hello-clinic-note/manifest.json
{ "id": "hello-clinic-note", "name": "Hello clinic note", "version": "1.0.0", "minAppVersion": "1.0.0", "description": "A first Extension — one command on the palette and a starter style for clinic notes.", "author": "Your name" }
File 2 of 2 — plugins/hello-clinic-note/main.js
/** * FocusCaseX Extension — Hello clinic note. * One command, one injected stylesheet, cleanup on unload — the same * shape as the shipped samples (registerCss, registerCommand, showToast). */ (function (ctx) { "use strict"; var css = [ ".clinic-note-starter {", " border: 1px solid var(--line);", " border-radius: 10px;", " padding: 14px 16px;", " color: var(--ink-2);", "}" ].join("\n"); ctx.registerCss(css); ctx.registerCommand({ id: "hello-clinic-note", title: "Hello, clinic note", icon: "FileText", run: function () { ctx.showToast("Hello clinic note is installed and running."); }, }); ctx.onunload = function () { /* the injected stylesheet leaves with the host cleanup */ }; })(ctx);
The catalog entry that publishes it
{ "id": "plugin:hello-clinic-note", "kind": "plugin", "name": "Hello clinic note", "tagline": "A first Extension — one command on the palette and a starter style for clinic notes.", "description": "A first Extension — one command on the palette and a starter style for clinic notes.", "author": "Your name", "version": "1.0.0", "category": "Writing", "tags": ["plugin", "writing"], "icon": "FileText", "meta": { "pluginId": "hello-clinic-note" }, "files": { "manifest": "plugins/hello-clinic-note/manifest.json", "main": "plugins/hello-clinic-note/main.js" } }

For the other kinds the same two-part pattern holds — a folder of files plus an entry that lists them. A theme entry's files.vars points at a JSON of design tokens; a template's files.body points at a markdown note with frontmatter (patient: MR-0000 and a type); a snippet lives in the catalog's top-level snippets array as { "id", "name", "file", "description" } pointing at one CSS file.

Test it locally

The CLI reads its marketplace from a URL, so you can point it at your own machine while you build. Make a mirror folder that looks like the site:

mirror/ catalog.json ← a copy of the catalog with your entry added to "items" plugins/ hello-clinic-note/ manifest.json main.js

Serve the folder with any static file server, then point the CLI at it and sync:

FCX_MARKET_URL=http://localhost:4319 fcx sync FCX_MARKET_URL=http://localhost:4319 fcx install plugin:hello-clinic-note

fcx sync fetches catalog.json from that URL and caches it; fcx install resolves the item by id, install code or name and writes its files into the workspace — the output shows the folder and the install code. Install by code works too: every item's FCX-XXXXXX code is derived from its id, so once your entry is in a catalog, its code exists and resolves the same everywhere — the site, the app and the CLI.

Share the mirror with the clinic. fcx serve hosts the synced cache for everyone: it prints a local URL, and a LAN address when a clinic network exists. No clinic network? The web workspace still opens as usual. Endpoints: /health, /api/catalog, /api/workbenches.

Submit it

  1. Add your entry to catalog.json in the public site repo (stromplayz/FocusCaseX) — in items, or in the top-level snippets array for a snippet.
  2. Add the files the entry points at, at exactly those paths: plugins/<slug>/, capsules/<slug>/, themes/<slug>.json, templates/<slug>.md or snippets/<slug>.css.
  3. Open a pull request — or hand the entry and files to the FocusCaseX owner, and the review takes it from there. Review fills in the marketplace metadata and marks reviewed items.

After it merges, one fcx sync picks the item up on every machine, the marketplace pages list it with its install code, and installs by code work in the app and the CLI alike. Shipping an update: bump version in the catalog entry and your manifest — the next install overwrites the old files.

Whole-workspace bundles

WorkBenches

A WorkBench is a fully prepared workspace setup packed into one install: Extensions, capsules, a theme, templates, snippets, starter pages and a settings snapshot. Installing one configures the whole clinic in a single step — the boards, the pages, the look and the note formats land together, matched to how a clinic like yours works. Where a single Extension adds one tool, a WorkBench assembles the entire setup — and it is still one confirm before anything lands.

Installing a WorkBench — every path

Four ways in, one destination: each ends on the app's confirmation screen, which lists every piece the bundle adds before anything lands. One tap on Apply installs the whole setup.

  1. From the website — tap Install on a WorkBench page here; the browser hands it to the app on this device and the confirmation screen opens.
  2. By code — in the app, Settings → Marketplace → Install by code, and type the WorkBench's FCX-XXXXXX code.
  3. From a file — a .workbench.json exported from another clinic installs under Settings → Marketplace → Install from file.
  4. From the CLI — fcx workbench list, fcx workbench show <id-or-code> to inspect every piece, then fcx workbench install <id-or-code>.

Switching WorkBenches like modes. Every WorkBench you install becomes a mode of the workspace — the app's WorkBenches tab shows each one as a chip, and one tap switches the whole workspace to that setup, with a switch-aware confirmation before anything moves. Switch back and forth as often as the day requires; modes are setups, not storage, and nothing is ever deleted.

Saving your own. Any clinic can turn its current workspace into a WorkBench: Settings → Marketplace → Save current setup as WorkBench snapshots the setup into one .workbench.json bundle — yours to keep, review and hand to a colleague or a second branch, who installs it in one step. The snapshot is setup only; nothing from your patient records goes into the bundle.

The boundary. Applying a WorkBench never deletes anything and never moves patient records. It adds tools, pages and settings; your case files, documents and history stay exactly where they are. Anything it installs can be removed later under Settings, piece by piece. Full detail: the WorkBenches page.

Neutral by design

Security and privacy

The licence. FocusCaseX is licensed per clinic, and the licence travels as a code: FCX-XXXXXX, bound to one email. At activation the code is checked against that email and tied to the device it ran on — which is why a forwarded installer is not a working app, and why every device a licence runs on is a known device.

What activation sends. Hardware identity only: device model, OS version, screen metrics, app build, locale and a per-device identifier. That is the complete list — it is what tells devices apart, and it is shown back to the licence owner. Patient records never leave the device during activation, and the periodic licence check sends the same kind of identity, nothing more.

Trusted devices. After activation the approval lives on the device itself — private to you. On Android it sits in the app's own internal storage, so clearing browser site data or switching browsers changes nothing; on the CLI the approval lives on the device itself, private to your user account. Deleting it — or uninstalling — is what makes a device ask for a code again. Every code carries a device limit, two devices by default; at the limit, the owner frees a slot by revoking a retired device or raises the limit.

Your records. Patient data lives in the workspace on your device. Day-to-day work needs no connection at all; first activation is the only moment that does. Export anything, any time — patients, notes and recalls come out as plain files you keep.

AI agents, on your terms. Agents reach the clinic only through MCP pairing — a code or QR you approve — with scopes you set, and every write shows a human-readable diff and waits for your confirmation. Revoke an agent any time. Full detail: licences and devices and MCP & AI agents.

When something's off

Troubleshooting

The things that come up most, each with a short answer. Clinic-side snags live on Getting started; CLI-side ones below and on the FCX CLI page.

What you see What to do
fcx: command not foundThe installer puts fcx in ~/.focuscasex/bin and wires your PATH, but a terminal opened before the install will not see it. Open a fresh terminal and run fcx again.
catalog fetch failsRun fcx sync to refresh the cache, or check the network. fcx vitals --offline passes with a cached catalog, so installs keep working without the network.
This screen needs an interactive terminalThe console and the storefront are full-screen views — run them in a real terminal, or use the plain paths: fcx catalog, fcx install <id-or-code>.
port already in useStart the registry server on another port: fcx serve --port <other>.
version mismatchRun fcx update — it prints the one-line command when a newer build ships — or re-run the install command, then check fcx --version.
the FCX- code is refusedCodes are exact — paste rather than retype, and make sure it is the code issued for your licence email. If the refusal says the device limit is full, your clinic owner moves the licence: the old machine is revoked, a fresh code is issued, and this machine activates.
fcx serve prints no LAN addressA LAN address appears only when a clinic network exists. With no clinic network, sharing over a local network is not available — the web workspace remains the way in, and it opens as usual.
Plain answers

FAQ

The questions clinics ask most, in plain words. The same list lives on the FAQ page.

Do I need the internet?
No. FocusCaseX works offline — your records live on your device and every board, page and note opens without a connection. The web app at focuscasex.vercel.app is there whenever you want it. The only online moment is the licence check when a device first activates.
What is FocusCaseX, in one sentence?
An offline-first clinic workspace for eye care: register patients, run refraction and exam flows, manage optics, dispensing and billing, set recalls — all on your own device, with pages you can read and print.
What is an Extension?
A small add-on that adds one feature to the workspace — an extra panel, an automation, a quick reference one tap away. You install it from the marketplace in one tap and remove it just as easily.
What is a WorkBench?
A whole clinic setup packed into one install — boards, pages, a theme, templates and starter settings. Applying one configures the workspace in a single step, and switching between installed WorkBenches works like switching modes. Your records never move.
What are capsules, themes, templates and snippets?
Capsules are ready-made boards you drop into any page. Themes change the look of every surface at once. Templates are pre-written clinical notes and letters. Snippets are small interface tweaks, like bigger headings.
How do I put FocusCaseX on another computer in my clinic?
Install the fcx command with one terminal line — the install guide has it — then run fcx setup and sign in with your licence email and the FCX-XXXXXX code issued for that machine. Every device counts against the licence's device limit.
What is the FCX code my clinic owner gave me, and where do I type it?
It is the activation code for your licence — eight characters, FCX-XXXXXX. In the app, a new device asks for it once at first launch, right after sign-in. On a computer, run fcx login in a terminal and answer the three prompts.
It says my code reached its device limit — what now?
Contact your clinic owner. They free a slot by revoking a device that is retired or lost, or raise the limit for your code — then the new device activates as normal.
I forgot my password — what now?
Ask your clinic owner — the password is reset on the licence. Nothing on your device changes, and your records stay exactly where they are.
Does my patient data go anywhere?
No. Records live on your device. Activation and the periodic licence check send hardware identity only — never patient records. Export anything, any time, as plain files you keep.
How do I update the app?
The Android app checks for updates on its own and tells you inside the app when one is ready — you confirm and it updates. The web workspace is always the current build; there is nothing to do.
How do I update the fcx command?
Run fcx update — when a newer build ships, it prints the one-line install command to run. Re-running the original install command works too; fcx --version confirms the build afterwards.
Can I share the app with the front desk over the clinic network?
Yes. When your clinic has its own network, fcx serve hosts the marketplace for every computer on it — the command prints the address to open. No clinic network? Everyone uses the web workspace — it opens as usual from anywhere.
How do I create my own Extension?
Follow the authoring guide — Create your own Extension: two small files, one catalog entry, a local test with the CLI, then a pull request to the marketplace. No build tools needed.
Is my licence tied to one device? What is a trusted device?
The licence belongs to the clinic and carries a device limit — two devices by default. A trusted device is one that has activated once; it is remembered, and it never asks for a code again.
How do I remove FocusCaseX from a computer?
Run the installer with --uninstall — the command is removed. To free that machine's slot on the licence, ask your clinic owner to revoke it.
Can two clinics share one licence?
No. One licence is one clinic — codes are bound to a single email, and the devices under it share one workspace. A second clinic needs its own licence and its own email.
Does installing an add-on touch my records?
Never. Installing or removing an add-on changes the setup only — your case files, documents and history stay exactly where they are.
What exactly works offline?
Everything you do day to day: patients, exams, notes, boards, recalls and every installed add-on. First activation on a new device needs a connection once; after that the device is trusted and the clinic runs without one.
Who do I contact?
Your clinic owner for codes, device moves and password resets. For everything else, FocusCaseX support answers licence mail directly — the docs pages always point at the current contact.
