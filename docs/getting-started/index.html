Getting started

Sign in, shape the workspace, install your first Extensions — your first day with FocusCaseX, in order.

The workspace works three ways, and they all open the same clinic: the web workspace in a browser, the Android app on phones and tablets, and a computer with the FCX CLI. This page walks the first day on each. The full guide covers everything in depth — its quickstart is the short version of this page.

Before you begin

Requirements

Pick the way that fits the room — the ways mix freely, since the same catalog and the same install codes wait inside every one of them: the web on the front-desk computer, the app in the testing room, the CLI wherever a keyboard is quicker.

A modern browser

For the web workspace at focuscasex.vercel.app — the whole clinic in a tab, nothing to install there, and the way in from anywhere.

Android 7.0 or newer

A phone or tablet for the app. Records live on the device, so an ordinary Android works — there is no server to rent.

Node 18+ (optional)

Only for the third way — the FCX CLI on a computer: macOS, Linux, or Windows through WSL or Git Bash. One curl command installs it; the guide's install walk-through and the FCX CLI page have the details.

First install — Android

Install the app

The install page links the latest Android build. After that, the app checks for updates on its own. The web workspace needs none of this — open focuscasex.vercel.app and sign in.

  1. Open the install guide and download the latest build linked there — the page always points at the current one, so there is no need to keep old copies.
  2. When Android asks, allow installs from that source — the browser or file manager that downloaded the file. It is a one-time switch per source; Android remembers it.
  3. Open the downloaded file, then open FocusCaseX from your app list.

Version updates. New builds arrive through the app's own update check — FocusCaseX tells you when one is ready and you confirm from inside the app. There is no store page to revisit; the install guide on this site always links the latest build.

The Android chapter of the full guide goes deeper on the app — first run, packs on the go, and what works offline.

The first five minutes

First sign-in and the workspace tour

The workspace opens after you sign in — nothing to configure first. On a device the licence has not met yet, one screen sits in between: activating the device. The modules sit in the sidebar, and each holds what its name says.

Activate this device

The first minutes, in order: the app checks workspace access, the sign-in screen asks for your licence email and password, and a device the licence does not know yet shows one more screen — Activate this device — before the workspace opens.

  1. Sign in with your licence email and password — the account your licence runs on. Keep me signed in on this device is ticked by default, so the next visit skips the form.
  2. When the app shows Activate this device, type the FCX-XXXXXX code the clinic owner issued for this device — it counts against the licence's device limit, two devices by default.
  3. The device is remembered from then on — the same device never asks again, a new phone or tablet simply asks once the same way, and a device the owner revoked asks again at next launch.

Devices and revocation. Activation ties each device to your licence, and revoking a device frees its slot. How codes, devices and revocation work — the full guide.

Third way — the FCX CLI

The workspace on a computer

The FCX CLI brings the same clinic to any computer that runs Node 18 — the same marketplace, the same WorkBenches, the same licence flow. One command installs it, and a short wizard does the rest.

One command, then the wizard

Paste the install line from the install guide into a terminal and the installer runs: it checks Node 18+, puts the fcx command in place and wires your PATH, then prints a short, plain summary of what it did — no storage paths, nothing to write down. Open a fresh terminal afterwards so the new command is picked up.

  1. Run fcx setup — the wizard asks step by step: where the workspace lives on this machine (it checks the folder is writable before moving on), a first fcx sync of the marketplace catalog, signing in, and a first WorkBench. The four steps in full: the guide's CLI setup chapter.
  2. Run fcx login if you skipped sign-in — your licence email, your password, and the FCX-XXXXXX code issued for this machine. One code per device; a trusted machine never asks again. The licence flow, in full.
  3. Run fcx install — any catalog item straight from the terminal, by name or by its FCX-XXXXXX code, with a summary of everything that landed.
fcx setup
# the wizard asks step by step — arrow keys move, enter picks
fcx login
# asks for your licence email, password and this machine's FCX-XXXXXX code — a trusted machine re-verifies quietly

The workspace page, from the machine itself

fcx open serves the workspace page on the machine itself — no internet needed. Everything it shows — licence status, installed items, the synced catalog, WorkBench bundles — is answered by the computer you run it on, and the page opens in the browser by itself.

On a clinic network, it also answers on the LAN address — printed right under the Local line — so the front desk or the testing room can open the very same page from another computer on that network. With no clinic network it still works locally, and the web workspace at focuscasex.vercel.app remains the way in from anywhere. The full walk-through: the guide's local-workspace chapter.

fcx open
# serves the workspace page from this machine and opens the browser — Ctrl+C stops it

One licence covers the computers too. Every machine activated with the CLI counts against the licence's device limit — the same limit the tablets already share. Devices, codes and revocation — the full guide.

Extensions, Capsules, Themes, Templates, WorkBenches

Installing Extensions

The catalog holds five kinds — Extensions add features, capsules add ready-made boards, themes change the look, templates drop in pre-written notes, snippets tweak the interface, and a WorkBench installs a whole setup at once. However an item arrives, it ends the same way: you see exactly what will be added, you confirm once, it lands.

WAY 1 — IN THE APP

Browse the Marketplace

The full catalog ships inside the app.

  1. Open Settings → Marketplace.
  2. Browse Extensions, Capsules, Themes, Templates or WorkBenches.
  3. Tap Install — it appears in your workspace right away.
WAY 2 — BY CODE

Install by code

Every marketplace item carries a short code, shown on its page on this site. Works the same on any device.

  1. Copy the code from any item page — it looks like FCX-XXXXXX.
  2. In the app: Settings → Marketplace → Install by code.
  3. Type or paste it, confirm the item, tap Install.
WAY 3 — FROM THIS SITE

Tap Install, confirm in the app

On any marketplace page, the install button hands the item to the FocusCaseX app on this device. The app opens on the install confirmation screen.

  1. Open an item page here and tap Install.
  2. FocusCaseX opens with a screen that lists everything that will be added — every Extension, capsule, template, snippet and page.
  3. Confirm once. The install runs with per-step progress and a final summary of everything that landed.
WAY 4 — FROM A FILE

Packs install straight from the file

A pack is one single file — an item zipped and given its pack extension. It installs straight from the file itself: no marketplace round trip, nothing fetched.

  1. Receive the pack — by email, on a USB stick, or from a shared clinic folder.
  2. Open the file on the device, or hand it to fcx install on a computer — either way, the file itself is the installer.
  3. The confirmation screen lists every piece before anything is applied — confirm once and it lands.

Nothing is deleted. Installing an item changes setup only — patient records stay on your device, and removing it later takes its tools and pages back out without touching them.

WorkBenches are the largest of these — one install sets up a whole workspace; the WorkBenches guide covers switching and saving your own. What a pack holds and how to make one is in the full guide, under one-file packs. If you work with AI assistants, they can find items for you while the install itself stays a human decision — see MCP & AI agents.

Keeping current

Updating

Three things stay current on their own — none of them needs a store page. The web workspace is always current; a browser refresh is all it takes.

The app checks for updates When a new build ships, FocusCaseX finds it in the update check and asks from inside the app. The install guide also always links the latest build.
The marketplace catalog refreshes itself New Extensions and new versions appear in Settings → Marketplace on their own — nothing to reinstall.
New builds are announced on the site The install guide is updated whenever a build ships, so it is the place to check what is current.
When something looks off

Troubleshooting

The things that come up most, each with a short answer. Plain-language questions of every other kind — where records live, what happens offline, who sees what — have short answers in the troubleshooting section of the full guide.

What you see What to do
Tapped Install on the site but the app opened without a confirmation screen Update the app to the latest build — older builds race the page load. Until you have updated, use Install by code instead.
Catalog not loading Check the network, then reopen Settings → Marketplace.
Install code not found The item may be newer than your build. Update the app, then retry the code.
Where did my patient records go? They never move: WorkBenches and Extensions are setup only. Check whether a different WorkBench is applied — switching back takes one tap.
fcx: command not found The terminal was open before the install; a fresh terminal picks up the new command. If something else on the computer looks off, run fcx vitals — a short health check that reports what is fine and what needs attention.
No LAN address under fcx open Normal when there is no clinic network — the page still works on the machine itself, and the web workspace remains the way in from anywhere.
Starting over

Uninstall or reset

Items come out one at a time or all at once, and your records are not part of either.

  1. Export what you need first. Patients, notes and recalls come out as plain files you keep — do this before any big change.
  2. Remove an item: Settings → Marketplace → Installed → tap Remove. Its tools and pages go; nothing else changes.
  3. Resetting the workspace means removing the Extensions and WorkBenches you installed — the setup goes, the records stay.

Records live on your device. Patient records stay in the workspace on the device — removing items or resetting the workspace never moves them.
