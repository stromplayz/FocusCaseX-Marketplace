Licences, devices & codes

Every device runs FocusCaseX under a licence, and every licence is a code — FCX-XXXXXX — bound to one email. This page covers what activation does, what it reads, where the approval lives, and how codes are issued and revoked.

Written for clinic owners on Android and anyone running the FCX CLI. For the install itself, see the install guide.

The licence model

Why a licence binds to a device

FocusCaseX is licensed per clinic, and the licence travels as a code: eight characters, FCX-XXXXXX, issued against one email. At activation the code is checked against that email and then tied to the hardware it ran on. From then on, the app on your device and the licence record are two views of the same fact — this code, this buyer, this machine.

That binding is what makes a forwarded APK stop being a working app. An installer passed along a group chat still installs, but at first launch it asks for a code, and a code cannot cover more devices than its limit allows. To run, the new device needs a sign-in with the buyer's email and a code issued for it — neither travels with the APK.

It also gives the owner a map. Every device a licence runs on registers itself the moment it activates — model, Android version, app build — so the question "which machines actually run FocusCaseX?" is a lookup, not a guess. When a tablet is sold or a phone replaced, the owner moves the licence from the old device to the new one.

Activation

How activation works

Activation runs once per device, and it is the same five steps on every phone, whether the clinic has one device or six.

  1. Install the app — the install guide links the latest Android build.
  2. Open it and sign in with your licence email and password — the email the licence was issued against.
  3. Enter the FCX-XXXXXX code issued for that email.
  4. The device registers — it reports its hardware details, is added to the licence record, and the workspace opens.
  5. Every later launch on that device passes without a code.

The code is a first-launch thing. The same person on the same device never sees it again — the approval is remembered on the device. A different device always asks for a code of its own, and a revoked device asks again at its next launch.

If the code is refused at step three, the likely causes come in order: a typo (codes are exact — paste rather than retype), a code issued for a different licence email, or a device limit that is already full. A full limit has a specific fix, described under Trusted devices below.

After activation

Trusted devices

A device that has activated is trusted, and the approval lives on the device itself. On Android it sits in the app's own internal storage — private to the app, not browser web storage, so clearing the browser's site data, switching browsers or signing out of Google changes nothing about it. On the CLI the approval lives on the device itself, private to your user account. Deleting it — or uninstalling — is what makes a device ask for a code again.

A new device never inherits an approval. It runs the same activation as the first one — sign in, enter a code — and while the licence is under its device limit, the existing code works on it; the owner can issue a fresh one instead if that is easier to hand over.

Every code carries a device limit — two devices by default, set by the owner when the code is generated and changeable at any time. At the limit, activation on a further device is refused until the owner makes room: revoke a device that is retired or lost, or raise the limit for that code. The refusal on the device names the reason, so there is no guessing about what went wrong.

Moving a licence to a new device takes a minute: the old device is revoked, a fresh code is issued, and the new device activates. The old device asks for a code at its next launch and cannot pass without one the owner issues — which is the point.

On the command line

Activate the CLI

The CLI activates the same way the app does — same code, same licence email — and one licence covers both ends. It needs the fcx command installed first; the two commands below do the rest.

Two commands

From a terminal on the machine you want to licence:

fcx activate
fcx status

fcx activate asks for your licence email and the FCX-XXXXXX code, checks them against the licence and writes the approval. fcx status prints what the CLI currently holds — no changes, just the state.

  1. Run fcx activate — it asks for your licence email and the code issued for it.
  2. The CLI checks the code and the machine appears on the licence record.
  3. Run fcx status — it prints the licence email, how many of the device limit are in use, and whether the approval is current.

Everything else the CLI does — installing from the catalog, hosting it on the clinic LAN, doctor, serve — is documented on the FCX CLI page.

FAQ

Questions

The five questions that come up most, with short answers. If yours is not here, FocusCaseX support answers licence mail directly.

Situation Answer
I lost the codeAsk FocusCaseX support — a fresh code is issued against the same licence email in a minute. Nothing changes on devices that are already trusted; a code is only needed for a device that has to activate.
I bought a new phoneWhile the licence is under its device limit, sign in on the new phone and enter the code — or a fresh one issued for it. At the limit, the old phone is revoked and a fresh code is issued: the licence moves, and the old phone asks for a code at its next launch.
What happens offlineA device that is already trusted keeps working — the approval lives on the device, and day-to-day launches do not need the network. First activation is the exception: the code has to be checked once, so that one moment needs a connection.
Two clinics on one licenceOne licence is one clinic. Codes are bound to a single email, and the devices under it share one workspace — a second clinic needs its own licence, its own email and its own codes.
Does revoke delete my recordsNever. Records live in the device workspace, and revoking touches only the licence check — the device asks for a code at its next launch, and the data is right where it was.
