Licences, devices & codes

Every device runs FocusCaseX under a licence, and every licence is a code — FCX-XXXXXX — bound to one email, with the clinic owner issuing a code per device. This page covers what activation does, what it sends, how trusted devices stay current, and how codes are issued and revoked.

Written for clinic owners and their teams on Android, and anyone running the FCX CLI. The one-page guide keeps a short recap in its security section; for the install itself, see the install guide.

The licence model

Why a licence binds to a device

FocusCaseX is licensed per clinic, and the licence belongs to the clinic. It travels as a code: eight characters, FCX-XXXXXX, issued against one email. At activation the code is checked against that email and then tied to the device it ran on. From then on, the app on your device and the licence record are two views of the same fact — this code, this clinic, this machine.

That binding is what makes a forwarded installer stop being a working app. An app passed along a group chat still installs, but at first launch it asks for a code, and a code cannot cover more devices than its limit allows. To run, the new device needs a sign-in with the licence email and a code issued for it — neither travels with the installer.

It also gives the owner a map. Every device a licence runs on registers itself the moment it activates — model, Android version, app build — so the question "which machines actually run FocusCaseX?" is a lookup on the admin Devices page, not a guess. When a tablet is sold or a phone replaced, the owner moves the licence from the old device to the new one; the steps are under Moving a licence below.

Activation

How activation works

Activation happens once per device, and it is the same five steps on every phone, whether the clinic has one device or six. The owner issues a code for each device as it joins — for a phone added later, that can be the existing code or a fresh one, whichever is easier to hand over.

  1. Install the app — the install guide links the latest Android build.
  2. Open it and sign in with your licence email and password — the email the licence was issued against.
  3. Enter the FCX-XXXXXX code issued for this device.
  4. The device registers — it reports its hardware details, is added to the licence record, and the workspace opens.
  5. Every later launch on that device passes without a code.

The code is a first-launch thing. A device asks once; from then on it is trusted and never asks again. A different device always asks for a code of its own, and a revoked device asks again at its next launch.

If the code is refused at step three, the likely causes come in order: a typo (codes are exact — paste rather than retype), a code issued for a different licence email, or a device limit that is already full. A full limit has a specific fix, described under Trusted devices below. New to the app? The full guide's quickstart walks a first device from box to workspace.

What is sent

Activation reads hardware identity and nothing else. The list is short on purpose: it is what the licence record needs to tell devices apart, and it is shown back to the owner, so a code never lands on an anonymous machine.

After activation

Trusted devices

A device that has activated is trusted, and the approval lives on the device itself. On Android it is private to the app, so clearing the browser's site data, switching browsers or signing out of Google changes nothing about it. It is never printed, never synced, and there is no file you can copy to move it somewhere else. On the CLI the same holds: the approval lives on the machine, private to your user account. Deleting it — or uninstalling — is what makes a device ask for a code again.

A new device never inherits an approval. It runs the same activation as the first one — sign in, enter a code — and while the licence is under its device limit, the existing code works on it; the owner can issue a fresh one instead if that is easier to hand over.

Every code carries a device limit — two devices by default, set by the owner when the code is generated and changeable at any time. At the limit, activation on a further device is refused until the owner makes room on the admin Devices page: revoke a device that is retired or lost, or raise the limit for that code. The refusal on the device names the reason, so there is no guessing about what went wrong.

Moving a licence to a new device

The approval cannot be handed over, and copying files will not move it — a new machine earns trust the same way the first one did, by activating. Three steps, all in the open:

  1. Free the slot — the clinic owner revokes the lost or retired device on the admin Devices page.
  2. Activate the new device — sign in with the licence email and enter the FCX-XXXXXX code. While the licence is under its device limit, the existing code works; the owner can issue a fresh one if that is easier to hand over.
  3. The old device stops — it asks for a code at its next launch and cannot pass without one the owner issues. Revoking touches the licence check only: the records on that machine are right where they were.
In the background

Staying current

A trusted device re-checks its licence on a schedule. The check-in sends the same hardware identity activation sent — nothing more — and its whole job is to keep the owner's admin Devices page showing the machine as current. Daily work never waits on it: a trusted device keeps working with or without a connection at that moment.

The re-check runs while you are signed in and stops on sign-out; signing in again starts it again. It needs nothing from you — no code, no prompts — and signing out is a local step only: it stops the check-in but does not free the device's slot. Slots are freed by the owner, by revoking on the admin Devices page.

On the CLI the check-in is its own small job: fcx alive start starts it, fcx alive status shows whether it is running, and fcx alive stop stops it. How often it runs is a CLI setting — anywhere from 5 to 1440 minutes, ten by default — changed with fcx config or with --interval when the check-in starts. The FCX CLI page lists the commands in full.

On the command line

Activate the CLI

The CLI activates the same way the app does — same licence email, same code, one licence covering both ends. It needs the fcx command installed first; the two commands below do the rest.

Two commands

From a terminal on the machine you want to licence:

fcx login
fcx status

fcx login asks for your licence email, password and the FCX-XXXXXX code, checks them against the licence and signs the machine in — the older name fcx activate does exactly the same thing. fcx status prints what the CLI currently holds — no changes, just the state.

  1. Run fcx login — it asks for your licence email, password and the code issued for this machine.
  2. The code is checked and the machine appears on the licence record, counting against the code's device limit.
  3. Run fcx status — it prints the licence email, how many of the device limit are in use, and whether the approval is current.

Trusted machines never re-enter a code: running fcx login again re-verifies the licence instead of asking. The full guide's account section covers the six account commands — including fcx device, which prints the same view of this machine the owner has on the admin Devices page — and everything else the CLI does, from the marketplace to hosting on the clinic LAN, is documented on the FCX CLI page.

FAQ

Questions

The questions that come up most, with short answers. The Updates collects the licence and data questions in one place, and FocusCaseX support answers licence mail directly.

Situation Answer
I lost the codeAsk FocusCaseX support — a fresh code is issued against the same licence email in a minute. Nothing changes on devices that are already trusted; a code is only needed for a device that has to activate.
I forgot the passwordAsk your clinic owner — the password is reset on the licence, by the owner. Nothing on your device changes, and your records stay exactly where they are.
I bought a new phoneWhile the licence is under its device limit, sign in on the new phone and enter the code — or a fresh one issued for it. At the limit, the old phone is revoked and a fresh code is issued: the licence moves, and the old phone asks for a code at its next launch.
What happens offlineA device that is already trusted keeps working — the approval lives on the device, and day-to-day launches do not need the network. First activation is the exception: the code has to be checked once, so that one moment needs a connection.
Two clinics on one licenceNo — one licence is one clinic. Codes are bound to a single email, and the devices under it share one workspace. A second clinic needs its own licence, its own email and its own codes.
Does revoke delete my recordsNever. Records live in the device workspace, and revoking touches only the licence check — the device asks for a code at its next launch, and the data is right where it was.
