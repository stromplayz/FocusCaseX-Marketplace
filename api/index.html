The catalog API

The marketplace is plain static files — every FocusCaseX client reads the same JSON you see below.

No database, no auth, no rate limits. Just files on GitHub Pages.

Endpoints

Every path below is a real file at the site root. Point any HTTP client at them, or just open them in a browser.

catalog.json
The full catalog — a marketplace header, the snippets list and 71 items across the four kinds
api/core.json
Current core version, minimum app version, announcement and featured picks
api/registry.json
The generated index every client merges at boot
releases.json
The app release feed — version, versionCode, core and notes for every build
themes/<id>.json
Theme palettes — the vars each theme applies to the workspace
templates/<id>.md
Template bodies — raw markdown, fetched and rendered on demand
plugins/<id>/
Extension sources — manifest.json plus main.js per folder
capsules/<id>/
Capsule layers — spec.mdui, style.css and logic.mdui, varying by capsule
snippets/<id>.css
Small CSS snippets, referenced by the snippets list in catalog.json

The shape of an item

One real entry from catalog.json, trimmed for the page. Every item carries the same fields:

{ "id": "plugin:note-templates", "kind": "plugin", "name": "Note Templates", "tagline": "Inserts a dated checklist template at the end of the active note with one command.", "author": "FocusCaseX originals", "version": "1.0.0", "category": "Writing", "tags": ["plugin", "writing"], "icon": "FileText", "released": "2026-01-24", "verified": true, "featured": false, "meta": { "pluginId": "note-templates" } }

Trimmed for the page — the real entry also carries a longer description and the meta/files block pointing at the item's sources. kind is one of plugin (Extensions), capsule, theme or template, and verified marks items reviewed and published by CaseX Labs.

Install codes

Every item id maps to a short, deterministic install code — FCX-XXXXXX. It is a 32-bit FNV-1a hash of the item id, rendered as six characters from an alphabet with no look-alikes: the digits 0/1 and the letters O, I, L never appear.

Same id, same code, everywhere — there is no lookup table to keep in sync. The identical algorithm runs inside the app, so a code typed under Settings → Marketplace → Install by code always resolves to the same item. Codes are accepted with or without the FCX- prefix.

Example plugin:optomize → FCX-84QQJD Type it in the app and Optomize opens with its confirm dialog.

Deep links

Install buttons on this site use a deep link. On a device with FocusCaseX installed, the browser hands the link straight to the app — the app shows the item and asks the user to confirm the install. Nothing installs without that tap.

fcx://install?id=plugin%3Aoptomize

The id is URL-encoded — the colon becomes %3A. If no app answers the link (FocusCaseX not installed, or the browser blocked the hand-off), the site falls back to a panel with the install code above.

How updates work

At boot, the app fetches catalog.json and merges the generated index in api/registry.json, so the Android app, the hosted workspace and this site all read the same list of items.

Version checks compare the installed build against the newest entry in releases.json; the current core version and its minimum app version live in api/core.json.

The index is rebuilt by scripts/build-registry.mjs on every push. CI re-runs the script, validates that the catalog and core files still parse, and fails the build if a committed index is stale.

Publishing

There is no toolchain to learn. If the files exist and the JSON parses, the change ships.

  1. Fork the repository, or open a branch on your copy.
  2. Commit your assets: a new entry in catalog.json plus the files it points to — plugins/<id>/, capsules/<id>/, themes/<id>.json or templates/<id>.md.
  3. CI validates the catalog and the index, and GitHub Pages serves the change — it is live the moment the push lands.
