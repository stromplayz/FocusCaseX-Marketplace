The protocol

What MCP is, in plain words.

Model Context Protocol (MCP) is an open standard that lets AI agents — Claude, Cursor, anything that speaks it — call tools on your behalf. The agent thinks in its chat window; the tools run against real software: search this, book that, install this.

FocusCaseX adds the other half: your clinic records become agent-accessible through a local, paired server — with a person at the approval layer. The app hosts the MCP server itself, on-device over your own Wi-Fi or on the web workspace at the endpoint above. You approve every connection, set every agent's scopes, and confirm every write.

Reads run free Once paired, the agent can search patients, open records, read today's day book, check stock — all the read tools below, no approvals needed. Reading changes nothing.
Writes pass through you Booking a visit, adding a note, installing a capsule — the agent proposes, FocusCaseX shows the change as a plain-language diff, and nothing applies until you tap Approve.
Builders, with your sign-off Agents don't just use the clinic — they can author for it: draft a capsule, scaffold an Extension, compose a whole WorkBench. You preview the result before anything installs.

Pairing

Connect an agent two ways. Both start in the app.

An agent points itself at your server and asks to pair. You finish the pairing inside FocusCaseX — a 6-digit code or a QR scan — and the agent is bound to this clinic install with the scopes you chose.

Code ConfirmationSettings → MCP

When an unpaired agent tries to connect, FocusCaseX shows a 6-digit code in the app. If the request is one you recognize, approve it — the agent is bound to this install, with its own scopes. No code you approved, no connection.

  1. The agent asks to pair. A pending request with its name and device appears under Settings → MCP, along with a 6-digit code.
  2. You approve. Deny and the agent stays locked out — there is no other way in.
  3. You set its scopes — read, write, build — and can change or revoke them any time.
Scan ModeSettings → MCP

FocusCaseX shows a QR code under Settings → MCP. Scan it from the agent's device — or from your phone — and the same pairing completes with zero typing. Same approval, same scopes, faster.

  1. Open Settings → MCP. The QR is on screen, ready to pair.
  2. Scan it from the agent's device or your phone.
  3. Approve in the app — paired, scopes chosen, done.

Per-agent scopes

Scopes chosen at pairing Each agent gets its own read / write / build mix, set when you approve it. A front-desk assistant can read everything and write nothing; a builder agent can do all three.
Writes always confirm Every write shows its diff and waits for Approve or Deny — unless you explicitly grant that agent a standing allowance, in which case its writes still land in the audit log.
A tray for pending actions The pending-actions tray in the app shows exactly what agents are waiting on, oldest first — the diff, the agent, the tool. Approve or Deny in one tap.
Revoke in one tap Every paired agent can be revoked under Settings → MCP. Revoking ends its access on its next call and clears its pending actions — no restarts.

Security & data posture

Where your data sits, and what crosses the line.

Local-first Records live in your clinic install — on your device or your hosted workspace. Agents read from the same install you use, not from a copy held elsewhere.
Codes and tokens stay put A pairing code or personal token leaves the clinic install only when you act — approve, scan, or paste it yourself. FocusCaseX never ships your credentials anywhere on its own.
Writes need a human No write applies without your confirmation, shown as a plain-language diff. Standing allowances are explicit, per agent, and visible under Settings → MCP.
Full audit log Every agent action is logged — time, agent, tool, and whether you approved it. One screen answers "what did the agent do?"
Revoke anytime One tap ends an agent's access. Pending, unapproved actions die with the pairing.
Deny is a real answer An unpaired agent gets one response — authorization required — and a pending request you can Deny. Nothing is exposed before you approve.
Questions

Good to know

Is my patient data sent to some cloud AI?
No. MCP connects your agent to your workspace over a connection you approved. Whatever the agent does with what it reads is governed by the AI service you chose and its terms — FocusCaseX itself never forwards your records anywhere.
Can an agent change my records?
Only writes you approve. Every write — bookings, notes, installs — shows a human-readable diff in the app and applies only when you tap Approve. Clinical records themselves have no delete tool; capsules and Extensions can be removed, again only on your confirmation.
What happens if an agent connects without approval?
It gets a single "authorization required" response, and a pending request appears under Settings → MCP with its name, device and the scopes it wants — plus a 6-digit code for you to check. If you don't recognize it, tap Deny — and it stays locked out.
What is a standing allowance?
Normally every write waits for your confirmation. A standing allowance is an explicit, per-agent grant that lets one specific agent write without asking each time — for agents you run unattended. It's visible under Settings → MCP and revocable like everything else; its writes still land in the audit log.
How do I switch MCP off?
Revoke agents under Settings → MCP — one tap each, effective on their next call, pending actions cleared. On a device you can also simply stop the host server.
Which agents can connect?
Anything that speaks MCP over HTTP: Claude Desktop, Claude Code, Cursor, custom scripts, scheduling automations, in-clinic kiosk assistants. If it can POST JSON-RPC, it can ask to pair — once you approve it.
