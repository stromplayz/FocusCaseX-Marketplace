The protocol

What MCP is, in plain words.

Model Context Protocol (MCP) is an open standard that lets AI agents — Claude, Cursor, anything that speaks it — call tools on your behalf. The agent thinks in its chat window; the tools run against real software: search this, read that, file this draft.

FocusCaseX adds the other half: your clinic records become agent-readable through a local, approved server. The app hosts the MCP server itself — on-device over your own Wi-Fi, or on the web workspace at the endpoint above — so there is no middle service holding your records, and nothing is readable until you approve the connection.

Your records, agent-readable Appointment boards, recall lists, optics logs — the pages you already keep become searchable and readable to the agent you approved. It answers from your workspace, not from a copy.
A local, approved server FocusCaseX hosts the MCP server itself. On-device it speaks only over your own LAN; on the web workspace it lives at the public endpoint. You approve every connection inside the app before a token exists.
Read-mostly by design Agents search, read, list and create pages. Editing and deleting are not in the toolset — the full reference is below, and that is the whole list.
Approval

No connection without you. Here is the whole flow.

Every step below happens inside FocusCaseX, under Settings → MCP & Automation. Follow it once per agent.

From request to token

  1. The agent requests a connection. An MCP client pointed at your server asks to connect. An unapproved client gets one answer — authorization required — and a pending request is recorded.
  2. FocusCaseX shows the request in Settings → MCP & Automation — with the agent's name, the device it came from and the tools it wants.
  3. You Approve or Deny. Deny and the agent stays locked out; there is no other way in.
  4. On approval, a scoped personal token is issued — fcxt_… — and shown once. Copy it now; it is never displayed again.
  5. Paste the token into the agent's configuration (the command below). From then on the agent can call only the documented tools — nothing more.
  6. Every call lands in the Activity log — the time, the agent and the tool. You can read exactly what happened, whenever you want.
  7. Revoke any time under Settings → MCP & Automation. Revoking kills the token instantly — the agent is out on its next call.

Tool reference

Four tools. That's the whole documented set.

Each tool does one job, and each card below says what it cannot do. Anything not on this list — edits, deletes, settings, billing — is not exposed to agents at all.

ToolWhat it doesWhat it cannot do
search_notes Search clinic pages by keyword — the same search the app itself uses. Returns titles plus short snippets, enough to find the right page fast. It does not return full page text. For the whole page, the agent follows up with read_note.
read_note Read one page in full, by its path — appointment board, recall list, a patient's visit page. Nothing it reads is changed — there is no edit tool at all.
create_note Create a new page under a clinic section — the agent's way to file a draft where you will find it. It cannot overwrite, edit or delete existing records. A create that lands on an existing path fails; existing pages stay yours.
list_patients List the patients in the workspace — name and MR chip, the same list you see in the app. It returns names and identifiers, not record contents — for those the agent uses search_notes and read_note.

Security

What stands between an agent and your records.

Approval first A connection only exists once you approve it in Settings → MCP & Automation. Without a token, an agent gets one answer: authorization required.
Scoped tokens Each approved agent holds one personal token (fcxt_…), issued at approval and shown once. It grants the documented tools — nothing else.
No silent edits The agent can create pages; it cannot change a page you already have. What it writes appears as new drafts, in plain sight.
No deletes There is no delete tool. Nothing an agent calls can remove a record.
Log everything Every call — time, agent, tool — lands in the Activity log. One screen shows exactly what happened and when.
Your network, your terms On-device, the MCP server answers only on your own Wi-Fi. On the web workspace, traffic runs between you and your agent — FocusCaseX never forwards your records anywhere.
Questions

Good to know

Is my patient data sent to some cloud AI?
No. MCP connects your agent to your workspace over your own connection. Whatever the agent does with what it reads is governed by the AI service you chose and its terms — FocusCaseX itself never forwards your records anywhere.
Can an agent change or delete my records?
No. The documented tool set is four tools: search_notes, read_note, create_note and list_patients. There is no edit-in-place and no delete — and create never overwrites an existing page.
What happens if an agent connects without approval?
It gets a single "authorization required" response, and a pending request appears under Settings → MCP & Automation showing who asked — name, device, tools. If you don't recognize it, tap Deny — and it stays locked out.
How do I switch MCP off?
Revoke the token under Settings → MCP & Automation. Revoking kills the token instantly — the agent is out on its next call, no restarts, no settings changes. On a device you can also simply stop the host server.
Which agents can connect?
Anything that speaks MCP over HTTP: Claude Code, Cursor, custom scripts, scheduling automations, in-clinic kiosk assistants. If it can POST JSON-RPC with a header, it can ask to connect — once you approve it.
